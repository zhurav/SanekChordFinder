# Проверка Sanek Chord Finder 0.9.0

## v0.9.0 — Chord Context Resolver

- Добавлен выбор только среди одинаковых pitch sets: бас, тональность с достаточной
  уверенностью, предыдущая гармония; LOAD HISTORY дополнительно учитывает две следующие.
  Это фиксированные музыкальные эвристики, а не статистическая модель вероятностей.
- Оба примера пользователя проверены во всех 12 тональностях: IVmaj7 → I6 → ii7 → V7
  и ii7 → vi7 → V7/V → V. Проверены конфликты с басом, симметричный dim7,
  отсутствие контекста, удержание названия и сброс после 30 секунд тишины.
- Перебраны 240 исходных аккордов × 13 вариантов баса × 25 вариантов тональности:
  состав нот сохраняется; поддержанный бас-корень имеет приоритет.
- Контекст тональности использует только однозначные наблюдения с длительностью.
  KeyDetector получил ограниченный буфер вместо выделения памяти при анализе;
  звуковой поток не выделяет память для контекста. История контекста ограничена 32 событиями
  и 30 секундами звучания. Тональность пересчитывается на сменах гармонии.
- Исправлена обнаруженная регрессия: слабый переход по квинте больше не переименовывает
  D#m7 в F#6. Аудиотест D#m7 → G#7 → C#maj7 четвертями проходит, максимальная задержка
  подтверждения 463 мс. Прежние 288 синтетических voicings, обращения, стерео и строй проходят.
- Итог: все 9 наборов CTest прошли (4 JUCE + 5 pure C++). Windows x64 Release VST3 собран.
- Реальный `тесткорд.wav`: в 4- и 8-тактовом захвате получен один цикл Am | C | Em | Em,
  начала 0/4/8/12, длина 16 долей; второй такт Em сохранён.
- Реальный `test.wav`, Extended, sensitivity 80: первый Csus2 теперь назван Csus2;
  во втором/третьем повторе остаётся эквивалентный Gsus4. Csus4 по-прежнему теряет F
  и определяется как C; Cmaj7 третьего повтора пропущен. Эти ошибки спектрального
  извлечения не объявляются исправленными контекстом. Auto BPM на этом файле не установлен.
- Архив: `build/SanekChordFinder-v0.9.0-Windows-x64.zip`. Проверены версия модуля,
  CRC архива и совпадение упакованного бинарника с Release. Установка и запуск новой
  сборки непосредственно в Ableton в этой проверке не выполнялись.


Дата: 10 сентября 2026 года.

## v0.8.1 — восемь тактов и затухание септим

- Добавлен независимый аудиофикстур из пользовательских нот:
  C / Cmaj7 / C7 / Csus2 / Csus4 / Cm / Cm7 / Cdim, один аккорд на такт 4/4 при 120 BPM.
  Септима затухает за 0,4 секунды, остальные ноты — за 2 секунды. До исправления тест выдавал
  лишние C/Cm, Gsus4 вместо Csus2 и Eb6 вместо Cm7. После исправления — ровно восемь событий.
- Краткое исчезновение части уже подтверждённого аккорда без новой атаки не объявляется сменой.
  Повтор Cmaj7 через такт и последующий настоящий переход в C проверены отдельно.
  Сохраняются тесты быстрых септаккордов и 40-мс посторонней вставки.
- Бас выбирает название только среди точных эквивалентов состава. Ноты в истории и таблице
  записываются гармонически: C7 — C E G Bb, Cm — C Eb G, Cdim — C Eb Gb.
- PositionInfo считывается только в аудиопотоке. PPQ, начало такта, счётчик тактов и размер
  используются для позиций истории при обычном воспроизведении и в лупе. Звуковой TempoTracker
  этих данных не получает. Повтор удержанного аккорда получает отдельную строку нового такта.
- Интеграционный тест проверяет BAR 1–8, имена и первую долю каждого аккорда в истории, UI и MIDI
  при включённом и выключенном лупе. У этого фикстура Auto BPM=0; экспорт всё равно работает,
  а MIDI помечается HOST 120 BPM. Все восемь аккордов занимают по четыре доли, конец файла — 32.
- Результат: `build/eight-bars-v081.mid`, интерфейс: `build/eight-bars-preview.png`.
  Это синтетическое воспроизведение последовательности, не запись пресета Analog Lab со скриншота.
  Старый пользовательский тест Am/C/Em/Em
  сохраняет четыре такта и правильные позиции.
- Финальная Windows x64 Release 0.8.1 собрана; все восемь наборов тестов прошли.
  Независимый MIDI-парсер подтвердил восемь правильных наборов нот, начало на долях

### Дополнительная проверка реального test.wav перед публикацией

Получен stereo PCM24 WAV, 48 кГц, 48 секунд: три повтора восьмитактовой последовательности.
Прогон текущего ChordAnalyzer в EXTENDED при Sensitivity 80, без данных транспорта:

- Cmaj7 в первом повторе появляется на 2,52 с вместо ожидаемой границы около 2 с;
  во втором — 18,01 с; в третьем, около 34 с, отдельное событие Cmaj7 пропущено.
- Csus2 определяется как Gsus4 на 6,02 / 22,02 / 38,01 с: состав нот эквивалентен,
  но требуемый корень C не выбран на этом тембре.
- Csus4 определяется как C на 8,01 / 24,01 / 40,01 с: это ошибка состава, требующая исправления.
- C7, Cm, Cm7, Cdim присутствуют во всех трёх повторах. Дополнительные C/Cm внутри
  подтверждённых септаккордов в этом прогоне не появились. Auto BPM остаётся неопределённым.

Версия 0.8.1 не считается полностью точной на данном пресете Analog Lab. Прохождение синтетических
тестов не заменяет эту проверку. Утилита AnalyzeChordWav теперь принимает чувствительность третьим
аргументом после `--extended`. Сам WAV и пользовательский Source.zip в Git не включены.

## v0.8.0 — бас, стерео, строй и гармонический контекст

- FFT вычисляется отдельно для каналов; складываются спектральные энергии. Сохранены
  288 тестовых звучаний всех 240 названий, тест быстрых септаккордов и защита от 40-мс вторжения.
- На аудио с полной противофазой L/R проверены C/E, C/G, Am/E, D/F# и G/B с точным MIDI-номером
  баса. Отдельный тест распределяет C и E/G между разными каналами: общий аккорд распознаётся.
- Бас проходит через ChordFrame, атомарную историю, снимок лупа, редактор Bass, XML состояния
  и MIDI. Независимые ожидаемые ноты пяти обращений проверены явно; для всех типов и басов
  из их состава проверены нижняя нота, число голосов и набор классов высоты. MIDI читается обратно
  с проверкой позиций, длительности и пар Note On/Off. Разбиение удержанного аккорда сохраняет бас.
- На синтетическом Am со строем −25/−5/+18 центов через 5 секунд получено −24.84/−4.82/+17.88.
  Проверяется сохранение имени Am и сброс калибровки. Это оценка общего смещения, не настройка
  каждой струны. Для неоднозначного/шумного спектра точный строй не гарантируется.
- Память имеет экспоненциальное затухание: около 69% через 10 секунд, 33% через 30,
  полное забывание через 60. Повторное подтверждение терции обновляет память, её собственная догадка — нет.
- KeyDetector использует confidence × audible duration с прежними гармоническими приоритетами.
  Проверены длинные C с кратким F#, устойчивое C major без ложных модуляций и подтверждённый
  переход C major → E major. KEY CHANGE отображается у момента подтверждения, ступени старого
  участка не пересчитываются по новой тональности. Длительность обновляется без новых смен аккорда.
- Пользовательский `тесткорд.wav` проверен с лупами 4 и 8 тактов, повторными проходами,
  остановкой и живым входом: результат Am/C/Em/Em на долях 1/5/9/13, конец 16 долей.
  Басовые MIDI-ноты: 45/48/52/52. Оценка BPM осталась приблизительной, 112–122 в этих сценариях;
  позиции полного лупа сохраняются благодаря PPQ, независимо от этой оценки.
- Проверка загрузки новой версии в Ableton и реального входа звуковой карты остаётся ручной.
- Финальная сборка Windows x64 Release 0.8.0 и все восемь наборов тестов прошли.
  Интеграционный тест проверяет C/E в живой истории и на экране, показ строя, редактирование Bass,
  сохранение в состоянии плагина и прекращение накопления длительности в тишине.
  Смена только баса C/E → C/G → C/E проверена без обязательного громкого удара.
  Интерфейс отрисован в `build/chord-track-preview.png` и проверен визуально.
  MIDI из пользовательского WAV дополнительно разобран независимым Python-парсером:
  960 PPQ, 16 долей, 12 Note On/Off, без незакрытых нот.
  Архив сборки: `build/SanekChordFinder-v0.8.0-Windows-x64.zip`.

## v0.6.7 — живой вход при остановленном транспорте

- Устранена регрессия обработки лупа: при остановленном транспорте callback анализатора
  отбрасывал распознанные аккорды. Теперь Listening управляет распознаванием независимо от Play.
- Для живого входа при остановке обновляются аккорд, уверенность, chroma и история. Неподвижная

- Добавлена проверка C/90 BPM при остановленном тестовом хосте 200 BPM с включённым лупом
  и неподвижной PPQ-позицией. Проверяются отображаемый аккорд, уверенность, chroma, история,
  независимый BPM, отсутствие выдуманного полного прохода и отключение через Listening.
- HostLoopTests дополнен живой игрой после остановки: распознавание работает, а опубликованный
  MIDI-луп сохраняет свои аккорды, позиции и длину. Проверка внутри Ableton остаётся ручной.
- Четыре набора JUCE/integration прошли после финальной сборки; сценарий с пользовательским WAV
  также прошёл. Собран Windows x64 Release VST3 0.6.7, архив `build/SanekChordFinder-v0.6.7-Windows-x64.zip`.

## v0.6.5 — позиции из транспорта и полный проход лупа

- Предыдущие проверки 0.6.3/0.6.4 не воспроизводили работу транспорта. Они подтверждали
  разбиение уже заданных позиций, но не гарантировали правильное время реальной записи.
  Тест, считавший `Am@1, C@57, Em@60...` корректным повтором, заменён проверкой отказа:
  одинаковые названия без совпадающего ритма больше не доказывают наличие цикла.
- ONE LOOP записывает PPQ относительно начала лупа хоста. Ожидание, остановка и незавершённый
  первый проход не входят в готовый снимок. Снимок публикуется после полного прохода;
  следующий частичный проход или seek его не перезаписывают. Смена границ лупа очищает снимок.
- HostLoopTests подаёт звук через настоящий процессор и LOAD HISTORY, с Sensitivity 75%,
  EXTENDED и WHOLE BAR. Проверены лупы 4 и 8 тактов, три секунды ожидания, старт с середины,
  два полных прохода, пять секунд после остановки при включённом Listening и seek.
- Синтетический сигнал и пользовательский `build/user-chords.wav` дают четыре строки:
  `Am@1, C@5, Em@9, Em@13`, каждая по четыре доли; конец на 16 четвертных долях.
  Восьмитактовый проход сокращается до четырёх только после совпадения позиций повторов.
- `build/testchord-host-loop.mid` прочитан независимым Python-парсером: SMF type 0, 960 PPQ,
  A–C–E / C–E–G / E–G–B / E–G–B, парные note-off, без незакрытых нот.
- Отдельно проверены полный луп с единственным удерживаемым аккордом, сброс при изменении
  границ, обрезка последней ноты по концу лупа и экспорт половин такта 3/4 с дробными позициями.
- Auto BPM не использует темп хоста. Тесты 90 BPM при хосте 200 и 150 BPM при хосте 60 проходят.
  На повторяемых отрезках пользовательского WAV оценка звукового темпа остаётся неточной
  (примерно 114–122 BPM в этих сценариях); MIDI-позиции при этом остаются 0/4/8/12 и конец 16.
  Эта версия исправляет транспорт и длительности, а не точность алгоритма Auto BPM.
- Проверка непосредственно в Ableton не выполнена. Тестовый хост моделирует PPQ и границы
  лупа при 117 BPM; исходный WAV читается без изменения и без Ableton Warp.
- Все восемь наборов тестов прошли: четыре JUCE/integration и четыре чистого C++ ядра.
  Собран Windows x64 Release VST3; версия бинарного манифеста и интерфейса — 0.6.5.
  Архив для установки: `build/SanekChordFinder-v0.6.5-Windows-x64.zip`.
